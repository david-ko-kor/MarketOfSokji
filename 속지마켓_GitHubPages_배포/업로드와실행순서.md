# 속지마켓 GitHub Pages 업로드·실행 순서

정리일: 2026-11-02. 이 폴더는 웹 배포에 필요한 HTML·CSS·JavaScript·이미지·모델·OCR 파일을 모은 정적 사이트입니다. Node.js·npm·Python·DB 설치 없이 GitHub 웹사이트에서 업로드할 수 있습니다. 아직 GitHub에 업로드하거나 공개한 것은 아닙니다.

## 1. ZIP 압축 풀기
`속지마켓_GitHubPages_배포.zip`을 풉니다. 폴더 안에 index.html, signup.html, login.html, auth.html, product.html, agreement.html, receipt.html, assets, models, ocr-samples, vendor 등이 있는지 확인합니다.

ZIP 파일 자체를 GitHub에 올리면 사이트가 되지 않습니다. 압축을 푼 **폴더 안의 내용물**을 올립니다.

## 2. GitHub 저장소 만들기
1. GitHub에 로그인합니다.
2. 오른쪽 위 + → New repository를 선택합니다.
3. Repository name에 `sokji-market`을 입력합니다.
4. 수업용 공개 배포라면 Public을 선택합니다. 이 사이트 파일은 인터넷에 공개됩니다.
5. Add README를 켜고 Create repository를 누릅니다. 비공개 저장소에서의 Pages 이용 가능 여부는 요금제·조직 설정에 따라 다릅니다.

## 3. 파일 업로드
1. 저장소의 Code 탭에서 Add file → Upload files를 선택합니다.
2. 배포 폴더 **안에 있는 파일과 하위 폴더**를 업로드 영역으로 드래그합니다. 배포 폴더 자체를 통째로 감싸서 올리지 않습니다.
3. 업로드 결과에서 최상위에 index.html과 assets 폴더가 나란히 보이는지 확인합니다. `속지마켓_GitHubPages_배포/index.html`처럼 한 단계 안으로 들어가면 안 됩니다.
4. Commit changes를 눌러 main 브랜치에 저장합니다.
5. `.nojekyll` 파일이 업로드됐는지 확인합니다. Mac Finder에서 숨김 파일이면 Command+Shift+.로 표시할 수 있습니다. 누락됐다면 Add file → Create new file → 파일 이름 `.nojekyll` → 내용은 비워 둔 뒤 Commit changes로 추가합니다.

이 묶음은 한 번에 100개 미만이며 파일당 25MiB 미만으로 구성했습니다. 업로드가 중단되면 폴더별로 나누어 업로드해도 됩니다. 단, 하위 폴더 경로는 그대로 유지합니다.

정상 구조 예시:

```text
sokji-market/                 ← GitHub 저장소
├── index.html               ← 반드시 저장소 최상위
├── signup.html
├── login.html
├── auth.html
├── product.html
├── agreement.html
├── receipt.html
├── .nojekyll
├── assets/
├── models/
├── ocr-samples/
└── vendor/
```

## 4. GitHub Pages 켜기
1. 저장소 Settings → 왼쪽 Pages를 선택합니다.
2. Build and deployment → Source를 **Deploy from a branch**로 선택합니다.
3. Branch는 **main**, 폴더는 **/(root)**로 선택합니다.
4. Save를 누릅니다.
5. Actions 탭에서 pages build and deployment 실행이 완료되는지 확인합니다. Pages 화면의 Visit site 링크가 실제 공개 주소입니다.
6. 주소는 보통 `https://내GitHub아이디.github.io/sokji-market/`입니다. 저장소 이름이 다르면 마지막 경로도 달라집니다. 이 예시를 그대로 복사하지 말고 본인 Pages 화면의 링크를 사용합니다.
7. Pages 설정에서 Enforce HTTPS를 사용할 수 있으면 활성화합니다. 로그인 비밀번호 처리는 HTTPS 환경에서 확인합니다.

## 5. 공개 주소에서 실행 순서
1. Pages의 Visit site 링크로 메인을 엽니다.
2. 기본 상품 12개와 사진형 예시 이미지가 표시되는지 확인합니다. 이미지에는 AI 생성 여부가 표시됩니다.
3. 회원가입에서 테스트용 아이디·닉네임·비밀번호·학교 정보를 입력하고 숫자 확인을 진행합니다. 실제 다른 서비스의 비밀번호는 사용하지 않습니다.
4. 학교인증에서 학번 입력 → ‘원주중학교 샘플로 테스트’ → 학교명 인식 성공 → 가입 완료를 진행합니다. 이는 가상 학생증으로 하는 로컬 시연입니다.
5. 로그인합니다. 새 계정의 내 체험 잔액은 100,000원입니다.
6. 기본 상품 상세 → 거래 조건 확인 → 희망 일시·조건 동의 → 거래 요청을 진행합니다. 이 단계에서는 차감되지 않습니다.
7. 물건·상태 및 거래 조건 확인 두 항목을 체크 → 거래 완료 확인 모달 → 최종 확정합니다. 실제 돈은 이동하지 않습니다.
8. 확인증과 상장 수여 흐름을 확인합니다.
9. 본인 상품은 제품등록 후 판매 조건을 작성합니다. 본인이 자기 상품을 구매할 수는 없습니다.
10. 채팅은 브라우저 안의 시연이며 실제 다른 기기 사용자에게 전송되지 않습니다. 기존 채팅 위험 경고와 가격주의 표시는 채팅 안에서 확인합니다.

## 6. 현재 서비스의 저장 범위
공용 DB·서버 인증이 없습니다. 계정·상품·거래·잔액·채팅은 접속한 브라우저 localStorage에만 저장됩니다. 다른 기기·브라우저와 공유되지 않습니다. 브라우저 데이터를 삭제하면 이 기록도 없어집니다. 기존 로컬 미리보기 주소에서 만든 계정은 GitHub Pages에 자동 이전되지 않으므로 배포 주소에서 다시 가입합니다. 같은 GitHub 사용자 도메인의 여러 프로젝트는 localStorage를 공유하므로 동일 키를 쓰는 다른 속지마켓 배포본과 함께 테스트할 때 주의합니다.

## 7. 다음 수정본 올리기
배포 폴더에서 수정된 파일을 같은 GitHub 경로에 Upload files로 올리고 Commit changes합니다. main 변경 후 Pages 배포가 완료되면 새로고침합니다. HTML과 JS가 함께 변경되었을 때는 연결 버전도 같이 갱신해야 합니다. 브라우저 캐시로 이전 화면이 남으면 강력 새로고침합니다. 사용자 브라우저 저장 데이터는 파일 업로드와 별개입니다.

## 8. 문제 해결
- 404: index.html이 최상위인지, Pages가 main / (root)인지, 배포가 성공했는지 확인합니다.
- 이미지·OCR 누락: assets·models·ocr-samples·vendor의 경로와 파일명 대소문자를 그대로 올렸는지 확인합니다.
- 파일명만 표시됨: Pages의 Visit site가 아니라 GitHub 저장소의 파일 화면을 연 것입니다.
- 화면은 새 버전인데 기능이 안 됨: JS 파일도 함께 올렸는지 확인하고 강력 새로고침합니다.
- OCR 로딩이 오래 걸림: 첫 접속 시 내장 엔진 파일을 내려받습니다. 네트워크와 브라우저에 따라 걸리는 시간이 다릅니다.
- 스타일이 안 보임: 현재 Tailwind·글꼴은 외부 HTTPS CDN을 사용합니다. 학교 네트워크에서 해당 CDN 접근이 가능한지 확인합니다.
- 로그인 계정이 없음: 로컬 주소에서 만든 계정과 배포 주소의 계정은 별개입니다. 다시 가입합니다.
